01 What a Firewall Actually Does

The gatekeeper between your network and the world

A firewall sits between the Internet and your internal network. Every message going in or out has to pass by it first. Its job: decide what gets let in, and/or what gets let out.

Firewall as a secretary: to meet an executive, you talk to the secretary first, who decides if the meeting is reasonable and filters out the rest. Want to meet the chair of the CS department? Some filtering. Want to meet the President of the US? A lot of filtering. Same firewall, same idea — the strictness of the rules just depends on what's behind the door.
One-line definition to memorize: A firewall provides access control for the network.

Heads up: there's no standard, universally agreed terminology for firewalls across the industry — different vendors/books use slightly different names for the same ideas.

02 The Three Main Types of Firewall

Same job, different layer of the network stack

Each type of firewall looks at traffic from a different "altitude" — the higher up the stack, the more it can see, but the slower it gets.

Type Works at Sees
Packet filter Network layer IP addresses, ports, flags — headers only
Stateful packet filter Transport layer Everything above, plus whether packets belong to an ongoing connection
Application proxy Application layer The actual data/content inside the packet

There's also a Personal firewall — not a new technique, just any of the above three, scaled down for a single user or home network (see Section 8).

Exam trap: "Packet filter" and "stateful packet filter" are NOT the same thing — the word "stateful" specifically means it tracks ongoing connections. Don't mix them up.

A packet filter looks only at the packet's header and decides allow/deny based on:

What it can filter on

  • Source IP address / Destination IP address
  • Source port / Destination port
  • Flag bits (SYN, ACK, etc.)
  • Direction: egress (outgoing) or ingress (incoming)

Rules are written as an Access Control List (ACL) — note: a different meaning of "ACL" than you may have seen elsewhere in the course.

Action Source IP Dest IP Src Port Dest Port Protocol Flags
Allow Inside Outside Any 80 HTTP Any
Allow Outside Inside 80 >1023 HTTP ACK
Deny All All All All All All

Reading this ACL: rule 1 lets internal users make outbound web requests; rule 2 lets the web's responses back in only if the ACK flag is set (meaning it should be part of a connection someone inside already started); rule 3 blocks everything else by default.

Advantage Disadvantages
Speed No state (can't tell if a packet is really part of an existing conversation) · Can't see full TCP connections · Completely blind to application data

04 Attack: TCP ACK Scan

Exploiting the fact that packet filters have no memory

Normally a TCP connection starts with a 3-way handshake (SYN → SYN-ACK → ACK). An attacker skips all that and just sends a packet with the ACK bit already set — this violates the protocol, but a plain packet filter has no state, so it can't tell the difference between "this is part of an ongoing connection" and "this just showed up out of nowhere."

  • Attacker sends fake ACK packets to different ports, one at a time
  • Ports where the firewall blocks the packet → no response comes back
  • Ports where the firewall lets it through (because it looks like an ongoing connection) → the internal host replies with an RST since it never opened that connection
  • The attacker now knows exactly which ports are open through the firewall — without ever needing a real connection
    • Fix: A stateful packet filter defeats this attack, because it actually tracks which connections are truly established — a lone ACK with no matching handshake gets rejected instantly.

    Same idea as a packet filter, but it now remembers ongoing TCP connections and their flag history — and it can even track connectionless things like UDP-based DNS requests, matching a reply to the request that caused it.

    Advantages Disadvantages
    Does everything a packet filter does, plus tracks ongoing connections (defeats ACK scans) Still can't see application-layer data · Slower than a plain packet filter

    06 Application Proxy

    The firewall that actually reads the mail

    physical
    link
    network
    transport
    application ← proxy lives here
    A proxy is something that acts on your behalf. An application proxy takes incoming data, fully inspects it, and only then builds a brand-new packet to forward inward — nothing from the original packet passes through untouched.
    Advantages Disadvantages
    Complete view of the connection and the actual application data · Can filter bad content at the application layer (viruses, malicious Word macros) · Deep packet inspection, not just header inspection Slower (has to build a fresh packet) · Single point of failure
    Key exam point: Because the proxy builds a brand-new packet, an attacker can't sneak raw packets through directly — they have to convince the proxy itself to forward the message. This blocks some attacks a stateful filter can't stop (see Firewalk, next).

    07 Attack: Firewalk

    Using TTL tricks to map what's open behind a firewall

    Firewalk is a scanning tool. The attacker already knows the firewall's IP and the IP of one system just behind it.

  • Attacker sets the packet's TTL to exactly one more hop than the distance to the firewall, and picks a destination port to test
  • If the firewall blocks that port → nothing comes back
  • If the firewall allows that port through → the packet dies one hop past the firewall (TTL hits 0) and that router sends back a "time exceeded" error — which tells the attacker the port is open
    • Trudy

    Port 12345,
    TTL=4

    firewall

    Critical exam distinction: Firewalk works against a packet filter (which just forwards the original packet, TTL and all) but does NOT work against an application proxy — because the proxy builds a completely new packet with a fresh TTL, destroying the attacker's timing trick.

    08 Personal Firewalls & Defense in Depth

    Layering firewalls instead of trusting just one

    A personal firewall protects a single user or home network. It's not a new technology — it can use any of the same three methods (packet filter, stateful filter, or application proxy), just scaled down.

    Defense in depth means never relying on a single firewall. A typical layered architecture: Internet → packet filter → DMZ (public-facing servers like WWW, FTP, DNS live here, somewhat isolated) → application proxy → intranet, where each internal machine may also run its own personal firewall.

    Why a DMZ?

    • Public servers (web, FTP, DNS) need to be reachable from the Internet, but you don't want them sitting directly on your trusted intranet
    • The DMZ is a middle zone: reachable from outside, but isolated from the fully trusted internal network by another firewall layer

    09 Intrusion Detection Systems (IDS)

    What to do when the firewall isn't enough

    Concept Meaning
    Intrusion prevention The traditional focus of security — keep the bad guy out entirely. Authentication, firewalls, and antivirus are all forms of this. (Like locking your car door.)
    Intrusion detection Accepts that, despite prevention, someone will sometimes get in — so instead it watches for unusual activity and raises an alarm.

    Who's the intruder, and what do they do?

    • Could be an outsider who got past the firewall, or an evil insider already inside
    • They may launch well-known attacks, variations on known attacks, brand-new attacks, or even use your compromised system to attack someone else

    IDS grew out of simple log file analysis and remains a very active research area. (Note: how to respond once an intrusion is detected is a separate topic, not covered here.)

    By approach By architecture
    Signature-based · Anomaly-based Host-based · Network-based

    Almost every real IDS product can be classified using this 2×2 grid — no matter what the marketing brochure calls it.

    Host-based vs. Network-based

    • Host-based: watches activity on one machine — good for catching buffer overflows, privilege escalation. Little/no view of network traffic.
    • Network-based: watches traffic across the network — good for catching denial-of-service, network probes, malformed packets. Little/no view of what's happening inside a specific host. (Overlaps somewhat with what a firewall does.) Many real deployments run both.

    10 Signature-Based Detection

    Recognize the fingerprint of a known attack

    Example: failed login attempts can indicate a password-cracking attack. A signature rule might be: "N failed logins in M seconds → warn of attack." Because the rule is specific, the admin knows exactly what's suspected and can go verify (or dismiss it as a false alarm).

    Tuning the signature

    • N and M must be chosen carefully so false alarms aren't constant — usually based on studying normal behavior
    • Problem: if the attacker knows the signature, they can just try N−1 logins every M seconds to stay just under the radar — signature detection then only slows the attacker, it doesn't stop them
    • To be more robust, systems detect "almost-signatures" too (e.g. "about N attempts in about M seconds") using statistics/heuristics — but that risks raising the false-alarm rate if not done carefully
    Advantages Disadvantages
    Simple · Detects known attacks reliably · Tells you exactly which attack was detected · Efficient with a reasonable number of signatures Signature files need constant updating · List of signatures can grow huge · Only catches known attacks · A variation on a known attack may slip through undetected

    11 Anomaly-Based Detection

    Flagging "weird," not matching a known pattern

    Instead of matching known attack fingerprints, anomaly detection asks two hard questions: what counts as "normal" for this system? and how far from normal counts as abnormal? Statistics is the tool for both — the mean defines "normal," and the variance defines how much wiggle room counts as still-normal.

    Big warning from the slides: you must measure "normal" during representative, attack-free behavior — if you accidentally build your baseline while an attack is already happening, the attack itself starts looking normal!

    Statistical techniques used

    • Bayesian statistics, Linear/Quadratic Discriminant Analysis (LDA/QDA)
    • Neural nets, hidden Markov models
    • More exotic approaches: AI, even "artificial immune system" ideas

    Simple example — command sequences: monitor three commands: open, read, close. If Alice normally produces the pairs (open,read), (read,close), (close,open), (open,open), then a burst of pairs outside that normal set signals possible unusual activity.

    Adaptive example — file access rates: the system keeps a long-term average access rate H per file, compares it to the recently observed rate A, and computes a distance score (sum of squared differences). If the score stays below a threshold, it's called normal — and the long-term average is nudged toward the recent behavior each time (e.g. H = 0.2A + 0.8H), so the system's idea of "normal" keeps adapting.

    The catch — this is a favorite exam question: because the baseline adapts, an attacker (Trudy) who slowly and repeatedly nudges behavior toward what she wants (e.g., always accessing one particular file) can gradually convince the IDS that her activity is the new normal. "Going slow" can let an attacker win.
    Advantages Disadvantages
    Chance of catching brand-new, never-seen-before attacks · Can be more efficient (no giant signature database to check against) Not reliable enough to use alone today — must pair with signature detection · A flag only says "something's unusual," not what the attack actually is · Vulnerable to the slow "boiling frog" style attack above

    A more sophisticated real-world system combining both anomaly and signature detection is called NIDES. Even top security researchers are split on how promising anomaly detection really is — a well-known Defcon talk was literally titled "Why Anomaly-based IDS is an Attacker's Best Friend."

    One-Page Recap

    • Firewall's job: access control between the Internet and an internal network — decide what's let in and/or out.
    • Packet filter (network layer): fast, checks headers only (IP/port/flags), no memory of connections.
    • TCP ACK scan exploits a packet filter's lack of state — a lone ACK sneaks through looking like part of an existing connection.
    • Stateful packet filter (transport layer): tracks real connections, defeats ACK scans, but still can't see application content.
    • Application proxy (application layer): rebuilds packets from scratch after inspecting the actual data — slowest but most thorough, and immune to TTL tricks like Firewalk.
    • Firewalk exploits TTL + "time exceeded" messages to map open ports past a packet filter — doesn't work through an application proxy.
    • Defense in depth: layer multiple firewall types (packet filter → DMZ → application proxy → personal firewalls) instead of trusting one.
    • Intrusion prevention (firewalls, auth, antivirus) tries to keep attackers out; intrusion detection (IDS) assumes some will get in and watches for unusual activity instead.
    • Signature-based IDS: matches known attack patterns — precise but blind to new/varied attacks.
    • Anomaly-based IDS: flags statistical deviation from "normal" — can catch new attacks, but is vague and can be slowly trained to accept an attack as normal.

    Q: Why does a TCP ACK scan get through a plain packet filter but not a stateful one?

    A: A plain packet filter has no memory of ongoing connections, so a lone ACK packet looks legitimate. A stateful filter tracks real handshakes and rejects ACKs that don't belong to one.

    Q: Why doesn't Firewalk work against an application proxy?

    A: The proxy builds an entirely new packet before forwarding it, which resets the TTL — destroying the timing information the attack relies on.

    Q: What's the main weakness of signature-based detection?

    A: It can only catch attacks matching a known signature — new attacks or clever variations can slip through, and signature databases must be constantly maintained.

    Q: What's the main weakness of anomaly-based detection?

    A: It only flags that something is unusual, without saying what the attack is — and because "normal" adapts over time, a patient attacker can slowly retrain the system to accept malicious behavior as normal.

    Q: What's a DMZ for?

    A: A middle zone between the Internet and the trusted intranet, for servers (web, FTP, DNS) that need to be publicly reachable without sitting directly on the internal network.
